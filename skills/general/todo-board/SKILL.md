# Todo Board（个人看板任务跟踪）

通过终端 `todo` CLI 将多步骤或需改文件的任务同步到个人看板，确保任务进度跨客户端透明可追踪，并配合看板守门机制（`kanban_gate`）工作。

## 何时挂看板 vs 何时放行

| 任务性质 | 处理动作 |
|---|---|
| **较大任务**（多步骤、改项目源码/配置、跑较长构建或迁移） | **动手改文件前必须先挂看板**（查重认领 `todo agent` 或新建立项 `todo add`） |
| **一两步极小改动**（改单行配置、修个错别字，无需专门立项） | 若环境启用了看板守门 hook，先单独运行 `kanban-skip "<简短原因>"` 放行本会话 |
| **纯咨询 / 问答 / 代码只读分析** | **不挂看板**，也不运行 `kanban-skip` |

## 核心工作流

下述 `<Agent>` 按你当前实际运行的客户端名称填写（如 `Claude`、`Codex`、`OpenCode`、`Antigravity`、`Pi`、`Gemini`、`Cursor` 等）。

### 1. 动手前：查重并挂上看板

1. 单独运行查重，检查是否已有意思相近的未完成事项：
   ```bash
   todo list
   ```
2. **已有对应事项**（`<事项>` 可填事项 ID 如 `tmw...`，或标题中唯一的一段文字）：
   ```bash
   todo agent <事项> --where "<Agent> · 本机" --agent-note "<当前正在做什么>" --as <Agent>
   ```
3. **没有对应事项**：
   - 先运行 `todo groups` 查看现有卡片分组；选最贴切的一张卡片，若都不合适则填 `Agent`（CLI 会自动在看板顶部创建「Agent」分区）。
   - 新建事项并直接挂入执行态：
     ```bash
     todo add <卡片> "<一句话标题>" --status agent --where "<Agent> · 本机" --agent-note "<当前正在做什么>" --as <Agent>
     ```

### 2. 执行中与阶段收尾：同步状态

- **范围变化或做完等待用户验收**：
  ```bash
  todo set <事项> --agent-note "<一句话结果与待确认项>" --as <Agent>
  ```
  **硬约束**：状态必须保持 `agent`，**严禁自行执行 `todo done` 标为完成**，完成状态统一由用户确认。
- **卡住需要用户拍板决定**：
  ```bash
  todo set <事项> --status waiting --waiting-on "<一句话决策点>" --agent-note "<一句话背景或备选>" --as <Agent>
  ```

## 踩坑记录与安全红线（Gotchas）

- **每条 `todo` / `kanban-skip` 命令必须单独调用**：禁止用 `&&`、`;`、`|` 与其他命令拼在同一行执行——一旦同行后续命令返回非零退出码，会导致状态未正常记录或会话守门标记失效。
- **文案极简，一句话说清就不多写**：看板主要是给用户扫一眼回忆和跟进用的。标题、`--note` 与 `--agent-note` 一律保持简短人话（例如标题写 `"给博客加 RSS 全文输出"`，备注写 `"已沉淀 todo-board 并统一六端规则，待确认提交"`），禁止复制整段原始指令，也不要堆砌步骤流水账。
- **严禁写入敏感信息**：不要把任何密码、API Key、Token、内网凭证或敏感隐私写进标题或 `--agent-note`。
- **离线与缺命令容错**：如果当前机器未安装 `todo` 命令，或看板服务暂时连不上报错，**直接跳过看板操作继续完成主任务**，不要影响主任务推进，也不要循环重试。
