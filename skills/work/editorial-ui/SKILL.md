# Editorial UI（克制审美与反 AI 模板味前端准则）

AI 写前端的默认惯性是“填满”与“套模板”——给更多装饰卡片、更多阴影和更花哨的渐变。好界面的本质恰恰相反：**知道在哪里克制、在哪里留白，让内容与用户的操作意图成为唯一主角**。

## 一、两阶段工作流（先定克制契约，再写代码）

### 阶段 1：先立紧凑设计计划并做“去模板味自检”

新建页面或大幅改版前，先用几行话敲定 4 个维度，**不要一上来就闷头堆组件**：

1. **语境与受众**：这个界面到底服务于什么场景与情绪（如沉浸阅读、高频工具面板、数据检索）？用真实内容做设计，不拿假大空占位词糊弄。
2. **克制色板（4–6 个命名 Token）**：定好纸面背景、主墨色、次级辅助色、分割线与**唯一一个语义强调色**，同时兼顾亮色与暗色模式的对比度可读性。
3. **排版与空间节奏**：选定 1–2 套字体及清晰字号梯度；正文行宽控制在 `65–82ch` 以内，中文长文适当放宽行高至 `1.75–1.9`，用间距和细线建立层级，而非靠给每个块套大框。
4. **唯一视觉焦点**：把大胆的设计表达**只花在一处最值得记住的元素上**，其余周围保持安静克制。

**动笔前自检**：把方案拿去对照下面“AI 模板味黑名单”——如果有任何一处只是因为“平时 AI 都这么画”而不是为当前产品专门做的决定，先砍掉再写代码。

### 阶段 2：严守项目既有 Token 契约实现

- **改值不破坏契约**：修改已有前端项目时，先阅读其 `tokens.css` / `global.css` / 样式系统，复用既有 CSS 变量与组件边界；禁止随手硬编码散落的魔法色值、杂乱的 `z-index` 或破坏全局选择器优先级的补丁。
- **结构即信息，而非装饰**：边框、分割线、角标、序号（`01 / 02`）只在表达真实逻辑关系（如严格步骤或时间线）时使用；去掉纯粹为了“显得不空”而塞进去的装饰元素。
- **像写界面一样写文案**：用用户视角与主动语态（写 `保存更改` 而非 `提交`），同类操作全链路词义一致（按钮叫 `发布`，提示就叫 `已发布`）；空状态给出明确下一步指引，报错直说原因与解法，不写空洞道歉。

## 二、反 AI 模板味黑名单（高频避坑清单）

除非用户明确要求某种特定风格，否则**主动避开以下典型 AI 生成套路**：

- **无脑 SaaS 卡片套盒**：把所有内容切进一模一样的圆角大卡片 + 统一浅灰弥散阴影 + 背景铺廉价紫蓝或暖陶土渐变。
- **排版小聪明与伪装饰**：标题里强行把单个词标成异色或斜体；每个标题上方机械堆一行全大写宽字距眉标（`EYEBROW`）；无序列表乱加 `01 / 02 / 03` 编号；每个链接和按钮末尾都粘一个 `→`。
- **动效过载**：每个区块滚动时都 `fade-in + slide-up`，每张卡片 hover 都上浮发光。非用户触发的动画要极度节制；动效优先用于回应用户真实操作（展开、切换、确认反馈），并尊重 `prefers-reduced-motion`。
- **假大空指标栏**：不管什么页面开头先放三个“大数字 + 小标签”的统计卡片撑场面。

## 三、视觉实测闭环（拒绝盲写交差）

改完前端代码后，编译通过绝不等于界面好看：

1. **真实渲染巡检**：在有浏览器预览或截图评审工具（如本机 `edithere-web`）的环境下，亲自打开运行中的页面核对桌面端与移动端响应式布局、亮/暗色模式对比度、键盘焦点可见性及溢出错位。
2. **减法复核**：交付前像照镜子一样通看一遍页面——问自己**“能不能再摘掉一件多余的边框、标签或动效？”**，删到不能再删为止。
